## 1. 位置づけ

`スト６/VS_DB/<相手キャラ>/` に置く、**相手キャラの対策を記録する**ツール。
コンボ記録ツールが「自分が何をするか」を記録するのに対し、こちらは「相手が何をしてくるか、どう返すか」を記録する。

```
スト６/
├── ffmpeg.exe                  ← 共用
├── COMBO_DB/RASHID/         ← ラシードで何をするか（既存）
└── VS_DB/
    ├── テンプレート/           ← 雛形（コンボ記録と同じ運用）
    │   ├── matchup.html
    │   ├── compress.bat
    │   ├── clips/
    │   └── README.md
    └── ラシード/               ← ラシードにどう対処するか（本ツール）
        ├── matchup.html
        ├── clips/
        └── compress.bat
```

- ファイル名は `matchup.html` で固定（ポータルが `VS_DB/<キャラ>/matchup.html` を探す）
- コンボ記録ツールと共有するもの: 単一 HTML・自己書換保存・`clips/` + compress.bat・フォルダ接続・ダークテーマ・コマ送り再生・習得/お気に入りフラグ・作成日/更新日
- 共有しないもの: データ項目、フィルタ軸、レシピ表記の色分け（対策の補足は自由文なので色分けしない）

## 2. 記録する内容

### 2.1 対策メモ（1件 = 相手の行動1つ + 動画1つ）

「攻略タイトル + 補足の自由記述 + 動画」を基本構成とし、分類のための項目を少数だけ足す。フレーム情報は持たない。

| 項目 | キー | 必須 | 例 | 備考 |
|---|---|---|---|---|
| 攻略タイトル | `title` | ○ | `対ラシードのサイクロン対策` | 一覧の見出し |
| 自キャラ | `self` | ○ | `ラシード`、`ケン` | **複数キャラを使う前提**。入力候補は既存データから自動生成（固定リストにしない）。フィルタ軸 |
| 場面 | `scene` | | 立ち回り / 起き攻め（受け）/ 起き攻め（攻め）/ 画面端 / その他 | 固定選択。フィルタ軸 |
| 重要度 | `priority` | | 1〜3（★） | 既定 1。並び順とフィルタに使う |
| 補足 | `note` | | 自由文（改行可） | 「サイクロンはしゃがみガード後に 5HP が確定。上派生は…」のように書く |
| クリップ | `file` / `src` | | `clips/サイクロン対策.mp4` | 1件に1本。コンボ記録と同じ仕組み |
| 参考URL | `link` | | `https://youtu.be/...` | 対策動画やフレームデータへのリンク。1件に1つ |
| ID | `id` | 自動 | `mfx1a2b3` | 作成時に採番。習得・お気に入りのキー |
| 習得状況 | `learned` | | true | localStorage `matchup_learned:<相手キャラ>`（キーは `id`）+ HTML |
| お気に入り | `fav` | | true | localStorage `matchup_fav:<相手キャラ>` + HTML |
| 作成日 / 更新日 | `created` / `updated` | 自動 | `2026-09-19` | フォーム保存時に自動で付与。カードに「更新 日付」を表示 |

### 2.2 キャラ全体メモ（相手キャラに1つ）

- **特徴と立ち回り方針** の自由記述欄（`summary.overview`）。ページ上部、一覧の前に表示
- 例: 「ケンは通常技が長く、迅雷脚と波動拳が強いため立ち回りに注意。突進技には弱いので積極的に使う。」
- 更新日（`summary.updated`）を自動付与し、欄の脇に表示
- 相性や要注意技の一覧は持たない（補足に書く。必要になったら追加）

### 2.3 コンボ記録ツールとの違い

| 観点 | コンボ記録 | キャラ対策 |
|---|---|---|
| 1件の主語 | 自分の技 | 相手の行動 |
| 見出し | レシピ表記（色分け） | 攻略タイトル（プレーンテキスト） |
| 数値 | ダメージ、Dゲージ、SA | 重要度のみ |
| 分類 | 位置、タグ | 自キャラ、場面 |
| 並び順 | 記述順、ダメージ、Dゲージ、効率 | 記述順、重要度、更新日 |
| 全体メモ | なし | 特徴と立ち回り方針 |

## 3. 機能

優先度: **A** = 最初に作る / **B** = 次に作る / **C** = 保留

- **A** 一覧表示（カード）、フィルタ（自キャラ / 場面 / 重要度 / 習得 / お気に入り）、並び順（記述順 / 重要度 / 更新日）
- **A** 編集モード（追加・編集・削除・複製・並べ替え）、HTML保存、JSON入出力、相手キャラ名の設定
- **A** クリップ再生・コマ送り・フォルダ接続・ドロップで書き込み（コンボ記録と同一コード）
- **A** キャラ全体メモ（2.2）の表示・編集
- **A** 作成日・更新日の自動付与と表示
- **B** 全文検索（タイトル・補足）
- **B** 「今日の復習」= 重要度★3 かつ未習得 を先頭に出すボタン
- **C** コンボ記録ツールへの相互リンク

却下: フレーム情報の構造化、横断検索（ポータル側で不要と決定）

## 4. 技術方針

- `COMBO_DB/テンプレート/combo.html` をベースに、データ項目・フィルタ軸・フォームを差し替える。保存・接続・動画・フラグ管理・日付の処理はそのまま流用
- `<meta name="sf6-tool" content="matchup">` と `<meta name="sf6-tool-version">` を持ち、ポータルが種別とバージョンを判別できるようにする
- localStorage のキーは `matchup_learned:<相手キャラ>` / `matchup_fav:<相手キャラ>`。file:// では全ページで localStorage が共有されるため、コンボ記録の `combo_*` と衝突させない
- 自キャラの入力候補は `<datalist>` で既存の `self` 値から生成する
- クリップの fps・圧縮設定は compress.bat を共用（20fps、`スト６/ffmpeg.exe`）
- `VS_DB/テンプレート/` を用意し、新しい相手キャラはフォルダコピーで作る

## 5. データモデル

```json
{
  "opponent": "ラシード",
  "summary": {
    "overview": "…特徴と立ち回り方針…",
    "updated": "2026-09-19"
  },
  "entries": [
    {
      "id": "mfx1a2b3",
      "title": "対ラシードのサイクロン対策",
      "self": "ケン",
      "scene": "立ち回り",
      "priority": 3,
      "note": "しゃがみガード後に 5HP が確定。上派生は…",
      "file": "サイクロン対策",
      "src": "サイクロン対策.mp4",
      "link": "https://youtu.be/...",
      "learned": true,
      "fav": false,
      "created": "2026-09-10",
      "updated": "2026-09-19"
    }
  ]
}
```

- コンボ記録の `#combo-data` が配列なのに対し、こちらは `summary` を持つためオブジェクトにする
- `opponent` は `<h1>` と同期（コンボ記録の「キャラ名」と同じ仕組み）

## 8. 実装（2026-09-20）

`VS_DB/テンプレート/` に `matchup.html`（`sf6-tool` = matchup、version 1）、`compress.bat`（コンボ記録と同一）、`clips/`、`README.md` を作成。

### 8.1 実装内容と要件の対応

| 要件 | 実装 |
|---|---|
| 2.1 対策メモ | 1件 = 攻略タイトル（必須）+ 自キャラ（必須、`<datalist>` で既存値を候補表示）+ 場面 + 重要度（★1〜3）+ 補足 + 参考URL + クリップ + 習得/お気に入り + 作成日/更新日。**クリップなしでも登録可**（`file` 空。カードは「クリップ未配置」表示） |
| 2.2 全体メモ | 見出し直下の「特徴と立ち回り方針」。編集モードでテキストエリアになり「方針を保存」で `summary.overview` と `summary.updated` を更新 |
| 3 A: 一覧・フィルタ・並び順 | フィルタ: 自キャラ（データから自動生成）/ 場面 / 重要度 / 習得 / お気に入り。並び順: 記述順 / 重要度 / 更新日 |
| 3 A: 編集 | 追加・編集・削除・複製・↑↓、相手キャラ名の設定（見出し・タブ名・localStorage キーに反映）、HTML保存、配布用HTML、JSON入出力 |
| 3 A: クリップ | コンボ記録テンプレートと同一（コマ送り 1/20 秒、フォルダ接続、ドロップで書き込み、大文字小文字ゆれの吸収、`preload=metadata`） |
| 3 A: 日付 | フォーム保存・複製時に `created` / `updated`、方針保存時に `summary.updated` |
| 4 localStorage | `matchup_learned:<相手>` / `matchup_fav:<相手>`。**キーはクリップ名ではなく各対策の `id`**（作成時に自動採番、HTML に保存）。クリップなしの対策が複数あっても区別でき、クリップ名を変えてもフラグが残る |
| 4 ツール識別 | `<meta name="sf6-tool" content="matchup">` / `sf6-tool-version` = 1 |
| 4 導線 | ヘッダ左上「← 一覧」が `../../index.html` を開く |

### 8.2 コンボ記録との差分（コード上）

- データが配列ではなく `{ opponent, summary, entries }`。JSON読み込みは配列（entries のみ）も受け付ける
- `#combo-data` → `#matchup-data`、`COMBOS` → `ENTRIES`
- レシピ表記の色分け（`classify` / `renderRecipe`）とダメージ・Dゲージ・SA・タグは無し
- フィルタ軸の値を関数にして、自キャラの選択肢をデータから生成
- 各対策に `id` を持つ（コンボ記録には無い）。習得・お気に入りのキーに使う。id の無いデータを読み込んだときは自動採番
- クリップ名の重複チェックあり（同じ動画ファイルを2件で共有しないため）。クリップ名が空の対策は対象外
- 新規フォームの自キャラ既定値は、最も多く使われている自キャラ

### 8.3 未着手（B / C）

- 全文検索（タイトル・補足）
- 「今日の復習」（重要度★3 かつ未習得を先頭に）
- コンボ記録ツールへの相互リンク

### 8.4 確認したこと（headless Chrome）

- 表示: 方針の表示、3件（クリップなし2件、存在しないクリップ1件、お気に入り・習得済み各1件）、自キャラチップがデータから生成、JS エラーなし
- 機能: 方針の保存と更新日、対策の追加（作成日・更新日・id）、不正 URL の拒否、自キャラ必須、自キャラフィルタ、重要度ソート、相手キャラ名の変更（見出し・タブ・localStorage キー）、保存用 HTML の生成、複製、削除
- 修正した不具合: 習得フラグのキーがクリップ名だったため、クリップなしの対策が複数あると全部が習得済みになった → `id` キーに変更

## 9. 仕様変更（2026-09-20）— 項目の簡素化と「キャラ」タグ

**指示**: 場面・重要度・習得・お気に入り・並び順のフィルタを削除。項目自体もフォームから削除してよい。代わりに「キャラ」を追加し、「全キャラ共通」「ケン」「ラシード」などのタグ付けを可能にする。

### 9.1 変更後の1件の構成（2.1 を置き換え）

| 項目 | キー | 必須 | 備考 |
|---|---|---|---|
| 攻略タイトル | `title` | ○ | 一覧の見出し |
| キャラ | `self` | ○ | **「全キャラ共通」か自キャラ名**。入力候補は「全キャラ共通」+ 既存データの自キャラ名。新規時の既定値は最も多く使われている値（無ければ「全キャラ共通」） |
| 補足 | `note` | | 自由文 |
| 参考URL | `link` | | http(s) のみ |
| クリップ | `file` / `src` | | 任意。無くても登録可 |
| 作成日 / 更新日 | `created` / `updated` | 自動 | |

削除したもの: `scene`（場面）、`priority`（重要度）、`learned` / `fav`（習得・お気に入り）、`id`（フラグが無くなったため不要）、localStorage の `matchup_*` キー、並び順（記述順のみ。↑↓で並べ替え）。
3章の A/B/C のうち「今日の復習」は重要度と習得が無くなったため廃止。

### 9.2 フィルタ「キャラ」

- 値: すべて / 全キャラ共通 / 自キャラ名…（データから自動生成）
- **自キャラ名を選ぶと、そのキャラの対策 + 全キャラ共通の対策を表示**する。「全キャラ共通」を選ぶと共通のものだけ
- 同じチップをもう一度押すと解除

### 9.3 カード表示

- チップは「キャラ」1つだけ（全キャラ共通は灰色、自キャラ名は青）
- 見出し、補足、参考URL、クリップ名、更新日、編集モードの行ツール（編集 / ↑ / ↓ / 複製）

### 9.4 データモデル（v2）

```json
{
  "opponent": "ケン",
  "summary": { "overview": "…", "updated": "2026-09-20" },
  "entries": [
    { "title": "迅雷脚の派生対策", "self": "全キャラ共通", "note": "…", "link": "https://…",
      "file": "迅雷脚対策", "src": "迅雷脚対策.mp4", "created": "2026-09-18", "updated": "2026-09-20" }
  ]
}
```

v1 データ（`scene` 等を含む）を読み込んでも余分なキーは無視され、そのまま保持される。

### 9.5 確認したこと（headless Chrome）

- 表示: 方針、3件（全キャラ共通 / ラシード / ケン）、フィルタが「キャラ: すべて / 全キャラ共通 / ケン / ラシード」の1軸のみ
- 機能: ラシードで絞ると ラシード + 全キャラ共通 の2件、全キャラ共通で絞ると1件、再クリックで解除、方針の保存、追加（キャラの既定値と候補）、不正 URL 拒否、キャラ必須、相手キャラ名の変更、保存用 HTML の生成（learned 等を含まない）、↑↓、複製、削除

## 10. デザイン刷新の提案（2026-09-20）

**指示**: 機能は OK。ポータル（ライト・ポップ）との一体感を意識してデザインを見直したい。

### 10.1 共通で取り込むポータルの意匠

- 紙色の背景 `#f6f3ee`、白いカード、3px の黒線、硬いオフセット影、角丸 18px
- 見出しは Bebas Neue（相手キャラ名）、本文は Noto Sans JP。「VS / キャラ対策」のラベルはピンク `#ff3d7f`
- チップは黒線のピル。選択中は黒地に白
- 「← 一覧」もピル型のボタンに
- **相手キャラ色**（ポータルのキャラ色と同じ考え方）を対策側にも持たせ、見出しや帯に使う。matchup.html のデータに `color` を追加し、編集バーのカラーピッカーで設定する（新規項目）

### 10.2 4案（モック: `デザイン案_対策.html`、上部タブで切替。動画はラシードのクリップを流用）

| 案 | 構成 | 動画の見やすさ | 特徴 |
|---|---|---|---|
| **M1 ポータル直系** | 白地。名前 → 方針カード → チップ → 横長カード（左に動画、右に本文）を縦に積む | 白地の上に動画。周囲が明るいぶん、暗い動画はやや締まって見える | 現在の matchup.html の構成をそのままポータルの見た目にしたもの。迷いが少ない |
| **M2 見出し帯 + グリッド** | 上部はキャラ色のヒーロー（名前 + 方針）。対策はキャラ色の帯にタイトルを載せた縦カードをグリッドで並べる | 動画は小さめ（3列） | 件数が増えても一覧しやすい。全キャラ共通は黒い帯で区別 |
